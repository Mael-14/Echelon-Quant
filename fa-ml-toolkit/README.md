# fa-ml-toolkit

Multi-timeframe feature encoding, triple-barrier labelling, and the measurement
apparatus for deciding whether a trading model is worth building.

Lifted out of a live forex/synthetics agent so it can be reused. It is
self-contained: the only internal dependency is `forex_agent`, and every module
here is either a leaf or depends on one other module in this folder.

---

## What this is for

You give it OHLC history across several timeframes. It gives you:

1. **Five normalised features** per bar, from a structural frame plus an
   execution frame.
2. **Triple-barrier labels** for those bars — profit, stop, or timeout.
3. **A null test** that says whether any model could beat the base rate,
   *before* you spend a week training one.
4. **A sequential backtest** with managed exits, one position at a time.

Point 3 is the part most pipelines skip, and it is the reason this folder
exists. Read `docs/ADR-004-no-directional-model.md` before anything else.

---

## Read this before you train anything

The originating project ran these tools across 5 forex pairs (16 months of M5,
14 years of H4) and a Deriv synthetic index. Summary of what was measured:

| test | result |
|---|---|
| Unconditional barrier touch vs `1/(1+b)` | matches to within 0.005 — **martingale** |
| Best of 25,720 conjunctions, scored on its own training data | **−0.063 R/trade** |
| XGBoost top decile, at a horizon free of labelling artifacts | +0.07 points over base |
| Sequential backtest, 5,176 trades, gross of costs | **−0.0075 R, t = −0.87** |
| Same, across holds from 15 min to 72 hours (288× range) | flat at ~0.00 |

**Gross expectancy measured zero everywhere.** Costs then make it negative.
The features are not broken — they select structurally coherent trades that
behave exactly as a fair coin with those barriers should.

Two consequences worth carrying into a new project:

* **Meta-labelling cannot manufacture an edge.** It filters an existing one. If
  your primary is at zero, a secondary model has nothing to rank.
* **The bar is `cost / (1 + reward)`.** At M5 on a retail spread that is ~4
  percentage points of win rate. For scale, Renaissance operates on 0.75.

Deriv's volatility indices (R_10 … R_100) are generated by a cryptographically
secure RNG. They are provably unpredictable; do not train on them.

```

  models.py                 Bar, Tick, Timeframe, Side. Validates in __post_init__.
  config.py                 Env-driven settings (only needed by the downloaders).
  strategy/
    features.py             The 5-column encoder. Start here.
    indicators.py           EMA, ATR, RSI, MACD, swings, candlestick patterns.
    barriers.py             Triple-barrier resolution + the martingale null.
    expectancy.py           Breakeven probability, Brier score, calibration.
    ict.py                  ICT pattern features (FVG, order blocks, sweeps).
  execution/
    exit_policy.py          Break-even, trailing stop, time stop. Pure functions.

scripts/
  null_test_conditional.py  RUN THIS FIRST. Is there anything to find?
  train_scalp_model.py      Point-in-time cascade, triple-barrier, L1 logistic.
  search_combinations.py    Exhaustive conjunction search + XGBoost.
  backtest_scalp.py         Sequential backtest, one position, managed exits.
  download_*_training_data.py   Fetch history from MT5 / Deriv.

tests/test_features.py      23 tests. The encoder's contract.
data/deriv_history.json     Sample history so the scripts run immediately.
```

## Install

Install the toolkit as a package so `import forex_agent` resolves from anywhere —
the scripts no longer prepend to `sys.path`, and any service in the platform can
import it the same way.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -e '.[dev]'         # or, from the repo root: make install-ml
python -m pytest -q             # 27 tests should pass
```

Python 3.11 or newer; the suite runs on 3.12 in CI and on 3.14 locally.
`numpy`, `scikit-learn` and `joblib` are required. The rest are extras, each
needed by one thing only:

| extra      | pulls in              | needed by                                                 |
| ---------- | --------------------- | --------------------------------------------------------- |
| `search`   | `xgboost`             | `scripts/search_combinations.py`, which imports it lazily  |
| `download` | `httpx`, `websockets` | `scripts/download_deriv_training_data.py`                  |
| `pandas`   | `pandas`, `pandas-ta` | nothing — `indicators.py` falls back to equivalent pure-Python implementations when absent |
| `dev`      | `pytest`              | the test suite                                             |

`scripts/download_mt5_training_data.py` additionally needs `MetaTrader5`, a
Windows-only wheel that drives a desktop terminal over local IPC, so it is left
out of the extras entirely.

## The five features

`encode_features(macro_bars, micro_bars)` returns a `MarketFeatures` row, or
`None` when the inputs cannot support the calculation.

| column | definition |
|---|---|
| `macro_trend_score` | `(close_macro − EMA200_macro) / ATR14_macro` |
| `distance_to_support` | `(close_micro − nearest level below) / ATR14_micro` |
| `distance_to_resistance` | `(nearest level above − close_micro) / ATR14_micro` |
| `retracement_factor` | `(close − swing_low) / (swing_high − swing_low)` |
| `micro_wave_momentum` | `(close_micro − VWAP_micro) / ATR14_micro` |

**Every column is dimensionless.** Add a constant to every price, or multiply
every price by a constant, and the row does not move — the tests assert both.
That is what lets one threshold work across a 1.10-handle currency pair and a
46,000-handle index.

The frames are not hardcoded. `encode_features(d1, h4)` and
`encode_features(h4, m5)` are both valid; it only insists the macro frame is
the coarser one.

### Two traps that cost real time

* **Do not derive trade direction from a feature you then want to test.**
  Setting `side = sign(macro_trend_score)` and feeding `macro_trend_score *
  side` yields `|macro_trend_score|` — no negatives in 73,872 rows, and the
  feature can never be shown to matter. Sample both directions instead.
* **Structural distance is a threshold, not a slope.** "Price is bouncing on
  support" happens at `|d| ≈ 0`, and raw distance reaches ±370 micro-ATRs when
  the levels come from a daily frame. A linear model cannot express that; pass
  a bounded `exp(-|d|)` proximity alongside the clipped distance.

## Data format

Every script takes one JSON file shaped like this:

```json
{
  "EURUSD": {
    "5m": [{"epoch": 1747388400, "open": 1.12151, "high": 1.12152,
            "low": 1.1212, "close": 1.12146, "volume": 206}],
    "4h":  [...],
    "1d":  [...]
  }
}
```

`epoch` is the candle's **start**, in seconds, UTC. `volume` is optional but
needed for a true VWAP. Both downloaders emit exactly this shape, so anything
that writes it will work.

**Beware broker clocks.** MetaTrader reports timestamps in the *server's*
timezone with no zone attached, and brokers rarely run on UTC. Read as UTC, a
UTC+3 broker stamps every bar three hours in the future — which misaligns any
news filter and silently discards the most recent bars as "still forming".
Measure the offset against your own clock and subtract it.

## Choosing the cascade

Every script takes the cascade as flags rather than assuming one. The default is
**H4 analysis into an M1 trigger** (`--macro-frames 4h --exec-frame 1m`); the
frames the toolkit was originally written around are one flag away
(`--macro-frames 1d 4h --exec-frame 5m`).

Each macro frame must be strictly coarser than the execution frame, which the
scripts check and refuse rather than silently encoding nothing.

Two things follow from the execution frame automatically, and both matter:

| | why it is not a constant |
|---|---|
| **spread drag** | Cost in R is `spread / stop_distance` and ATR grows as √time, so drag falls as 1/√time: **0.017R at H4, 0.095R at M5, ~0.21R at M1.** It sets the breakeven line every verdict is measured against, so a frame-independent default would flatter a fast frame by more than 10×. **The M1 figure is extrapolated from M5, not measured** — re-measure it against a real Deriv spread before trusting an M1 result. |
| **execution window** | `momentum` is the close's distance from the session VWAP, and `vwap` anchors to the newest UTC day *in the window*. A day is 288 M5 bars but **1440 M1 bars**, so a fixed 400-bar window would silently re-anchor to a partial session at M1. The default is now one whole session, floored at 400. |

The bundled `data/deriv_history.json` carries no `1m` frame, so the default
cascade skips every symbol until fresh history is downloaded:

```bash
python scripts/download_deriv_training_data.py --exec-frame 1m --count 40000 --raw data/deriv_m1.json
```

## Suggested order

```bash
# 1. Is there an edge at all? Read the MDE column before the z column.
python scripts/null_test_conditional.py --history data/deriv_m1.json --macro 4h --micro 1m

# 2. Only if step 1 deviates: build labels and fit.
python scripts/train_scalp_model.py --history data/deriv_m1.json --macro-frames 4h --exec-frame 1m

# 3. Search interactions; compare against XGBoost.
python scripts/search_combinations.py --cache dataset.npz --hold 24 --exec-frame 1m

# 4. What an account would actually have done.
python scripts/backtest_scalp.py --history data/deriv_m1.json --structure-frame 4h --exec-frame 1m
```

Score everything in **R after cost**, never accuracy. A filter that lifts the
win rate while raising the cost hurdle by more has improved nothing — and that
is a real failure mode, not a hypothetical: selecting deep pullbacks tightens
the stop, and `cost = spread / stop` rises faster than the win rate does.
